# Plan: v2.24 prime-agent harvest — staleness, learnings lifecycle, observed usage, salvage, continuity

## Mission

Port the five performance-relevant mechanisms identified in the 2026-08-05 prime-agent deep
comparison (PrimeIntellect-ai/prime-agent, MIT) into Elves as v2.24.0: (1) worktree-fingerprint
staleness detection that stops futile re-drives, (2) a learnings lifecycle with typed edits,
history, and rollback, (3) an observed-usage ledger surfaced into Session Budget, the Elves
Report, and calibration, (4) worker-death salvage previews for all supervised workers, and
(5) an opt-in, operator-owned continuity resume watchdog for full-runs. Done means: all Master
Acceptance rows green, `verify_repo.py --ci` and the consistency corpus green, CHANGELOG v2.24.0
with upstream attribution, a landable reviewed PR. Ideas are adapted with credit; no upstream
code is vendored.

## Scope

### In Scope

- New `scripts/cobbler_runtime/worktree_fingerprint.py` + futile re-drive classification wired
  into the full-run labor-completeness path and the legacy bounded route.
- New `scripts/cobbler_runtime/learnings_ledger.py` + `cobbler_agents.py learnings …` verbs;
  `references/learnings-template.md` upgrade (stable ids, evidence pointers, expected-outcome
  notes, generated digest, tracked history sidecar).
- Observed-usage aggregation building on `sessions.py` (`UsageRecord`, `parse_usage_payload`),
  a `reports_usage` capability row in `host_profiles.py`, an additive `usage_observed` block in
  `.elves-session.json`, Session Budget lines, an Elves Report panel, and an optional additive
  usage field on calibration rows.
- Salvage-preview harvesting on abnormal worker termination for native workers and full-run
  workers, generalizing the existing Fugu timeout-salvage behavior.
- `scripts/resume_watchdog.py` + `cobbler_agents.py continuity install|status|remove` +
  launchd/systemd user-timer templates + doctor checks (default off).
- Contract-language harvests (current-state-audit phrasing; optional council pre-check pattern),
  glossary entries, consistency pins, guide updates, CHANGELOG, version bump, release.

### Out of Scope

- Any IPython/programmatic kernel substrate, REPL tool surface, or Python-backed skill runtime.
- Direct agent-to-agent messaging or any mid-run steer channel (packet-sent-exactly-once stands).
- Token-based quota or usage-pressure **inference** (#199 stands; this plan records observations
  and honors explicit user ceilings only).
- Recursion depth changes (workers still never spawn workers).
- A resident daemon tier, supervisor processes, or anything beyond the OS-timer watchdog in B6.
- Parallelves runtime lane supervision (#208 remains a separate future decision).
- Vendoring, forking, or translating prime-agent source code into this repo.

## Product decisions (locked for this run)

1. **Attribution, not vendoring.** Every ported mechanism is an original stdlib implementation.
   CHANGELOG and `docs/` credit `PrimeIntellect-ai/prime-agent` (MIT) with the upstream commit
   SHA recorded at staging. No upstream code, prompts, or files are copied into the repo.
2. **Learnings format:** `learnings.md` stays human-readable markdown and stays the authoritative
   content surface. Entries gain stable ids (`[L#]`) plus optional `(evidence: …)` and
   `(expect: …)` suffixes; history lives in a tracked append-only `learnings-history.jsonl`
   sidecar next to it (caps mirroring the calibration store: bounded records and bytes, atomic
   flock append, malformed-tail skip). Files without ids remain fully valid; `learnings migrate`
   is optional and never automatic; freehand agent edits between ledger operations must be
   preserved verbatim (re-parse before apply; refuse rather than destroy on unparseable input).
3. **Usage honesty:** the ledger records **observed** usage from transports that report it, per a
   `reports_usage` capability row in `host_profiles.py`. Unknown remains the literal string
   `unobserved` — never zero, never estimated. Cache-read tokens are excluded from any ceiling
   comparison. Observed usage is never an input to worker routing (routing stays deterministic
   and model-free) and never landing authority. An explicit user-set `usage_ceiling` is advisory:
   crossing it produces a checkpoint event and notification, never a stop; Forbidden Stop Reasons
   is extended with "advisory usage ceiling crossed."
4. **Futile re-drive semantics:** a re-drive candidate whose worktree fingerprint is identical to
   the previous substantive failure of the same batch, with the same failing-evidence class, is
   classified `redrive_futile:workspace_unchanged`. It **consumes one re-drive from the budget**,
   the identical packet is **not** relaunched, and the run escalates along the existing ladder
   (split the batch / host-native takeover / hard stop). Fingerprint capture errors and
   over-cap trees degrade to `changed` — a fingerprint failure can never manufacture futility.
   Transient-failure retries (escalating backoff) remain exempt exactly as today.
5. **Continuity boundaries:** Elves remains not-a-runtime-scheduler — the OS owns the timer;
   Elves ships templates, a manager CLI, a stdlib watchdog script, and doctor checks only. The
   consistency pin is **revised to say exactly that**, not deleted. Default off; nothing installs
   a timer implicitly. Scope is trusted full-run resume only (host-native driver sessions cannot
   be revived headlessly and are documented as out of reach). The watchdog invokes the existing
   idempotent resume path, which keeps all v2.23/v2.23.1 fail-closed behavior: terminal or
   unverifiable event logs are refused byte-for-byte unchanged. A single-flight flock claim file
   makes overlapping timer fires safe; missed fires coalesce because each fire is a stateless
   check (claim-before-deliver discipline).
6. **New coined terms are capped at three** — *futile re-drive*, *learnings ledger*, *continuity
   watchdog* — each with a glossary entry naming its user-visible overnight-run value (fewer
   wasted re-drives; auditable/reversible memory; no lost nights to a dead session). No other new
   terms, config keys, or subsystems (Code Quality Philosophy #10).
7. **Additive schemas only:** `.elves-session.json` gains optional `usage_observed`; calibration
   rows gain an optional usage field with reader tolerance for its absence; existing sessions,
   stores, and legacy learnings files stay readable. Public-API snapshot changes go through
   `api-break-approvals.json` only for intentional additions.

## Non-Negotiables

- Stdlib only; no new runtime dependencies; no code, prompts, or files copied from prime-agent —
  ideas with attribution, implementations original.
- Fail-closed asymmetries are inviolable: fingerprint error ⇒ `changed`; unknown usage ⇒ literal
  `unobserved`; watchdog never resumes terminal or unverifiable runs; nothing in this plan gains
  or grants landing authority.
- Advisory-only surfaces stay advisory: usage ceilings, fingerprint deltas, digests, and salvage
  text never stop a run, never alter routing, and never grant or deny readiness by themselves.
- Every normative sentence restated on any surface gets its consistency pin in the same commit;
  `verify_repo.py --ci` green at every batch Close.
- Additive schema changes only; legacy sessions, stores, and learnings files stay readable.
- The user owns whether Elves may merge. Default is user-merges; merge-on-green or an explicit
  reviewed-PR landing command (`\land-pr` or `/land-pr`) is the only opt-in. In either opt-in
  path, Elves lands a regular merge commit (never a squash) only after final readiness.

## Test Strategy

- **Primary gate:** `python3 scripts/verify_repo.py --ci` (compile, secret scan, API approvals)
  plus the focused unit suites added per batch under `tests/`.
- **Secondary gate:** `python3 scripts/check_repo_consistency.py` (phrase-pin corpus) after every
  docs-touching batch.
- **Terminal gate:** `verify_repo.py --final-readiness` at the attested tip.
- **Hermeticity:** all new tests follow the house convention — children run with fd-0 devnull and
  explicit timeouts; no live network; OS timer interactions mocked; timing-sensitive tests use
  the existing hardening patterns (generous floors, event-driven waits).
- **Durable docs:** promote reusable lessons to `learnings.md` (via the new ledger once B2
  lands — dogfood it) and `.ai-docs/gotchas.md` for any hidden dependency discovered.
