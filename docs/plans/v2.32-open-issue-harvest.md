# Plan: v2.32 open-issue harvest

## Mission

Work the ten open `aigorahub/elves` issues in decreasing order of return. Four of them
(#244, #245, #247, #248) were already fixed by merged PR #241 and only need verified closure.
Four carry real code work (#260, #242 residual, #249 residual, #258), one is a larger plumbing
task (#243), and one (#246) needs a supervised live OS-timer trial that no code change can
substitute for. Done means: every open issue is either fixed with proof, closed with evidence,
or explicitly skipped with a stated reason; the full `verify_repo --ci` battery is green; and
the branch is a landable PR that nobody has merged.

---

## Scope

### In Scope
- `scripts/cobbler_runtime/prewalk.py` — guide prompt artifact contracts and lenient
  normalization (#260).
- `scripts/cobbler_runtime/full_run_monitor.py` — forced events re-read at the first validated
  terminal report (#242 residual).
- `scripts/cobbler_runtime/learnings_ledger.py` — `_section_at` digest-interior skip
  (#249 round-4 closer).
- `scripts/cobbler_runtime/native_worker.py` — observed effective route and evidence tier in
  prewalk qualification (#258).
- Observed-usage wiring at the native-worker close and full-run reconcile paths (#243).
- Tests for every behavior change, plus CHANGELOG and reference-doc updates.
- GitHub issue closure and comments for issues settled by this run or by PR #241.

### Out of Scope
- Merging this branch, or any `/land-pr` action. The user owns merge.
- Migrating the live `docs/elves/learnings.md` to `[L#]` ledger form (#249 item 1) — a locked
  operator decision, not an agent call.
- Removing the `--json` flag from the five v2.24 verb families (#249 item 3) — the maintainer
  recommendation on record is to keep it; changing it churns the tracked API-surface snapshot.
- Live activation of launchd/systemd timers (#246). It needs a disposable full-run, a real
  machine sleep, and supervised observation.
- Making an observed route change a hard qualification requirement. #258 states this must not
  fail closed on hosts that publish no signal.
- Any change to the thin safety kernel's authority boundaries.

### Batch 1 [B1]: State the prewalk artifact contracts and stop terminalizing on prose bounds (#260)

- **Intent / why:** The guide prompt tells the model to mirror a TODO "using the Elves prewalk
  TODO schema" and never states that schema. Three separate live failures followed from this on
  one run: an unstated TODO dialect, unstated checkpoint fields, and an unstated 500-character
  summary cap that terminalized a 44-minute successful execution phase. There is no automatic
  recovery for artifact-invalid transitions, and the registry blocks relaunch under the same run
  id, so each miss costs a full manual re-drive.
- **Non-obvious rationale:** the fix is two-sided on purpose. Stating the contract prevents the
  miss; lenient normalization prevents the *cost* of a miss where leniency is honest. Leniency
  must never fabricate evidence: a prose `validation` string may not become a
  `{command, exit_code}` record, because that would invent an exit code the guide never observed.
  Identity fields (run id, session id, schema version, `PW-##` ordering, `ready_for_execution_model`)
  stay strict.
- **Build On targets:** `guide_prompt()` already spells out checkpoint *kinds* concretely; extend
  the same treatment to the two artifact shapes. `_required_text` already carries `max_chars`.
- **Owned surfaces:** `scripts/cobbler_runtime/prewalk.py`, `tests/test_native_worker_prewalk.py`,
  `references/prewalk.md`, `CHANGELOG.md`.
- **Forbidden surfaces:** `native_worker.py` qualification logic (that is B4), run memory,
  credentials.
- **Acceptance evidence:** the rendered guide prompt contains a literal example of both artifacts;
  a checkpoint whose summary exceeds the cap validates with a truncated summary rather than
  raising; an absent `validation_attempted` normalizes to an empty list; identity strictness is
  test-pinned unchanged.
- **Failure modes / pitfalls:** the guide prompt is hashed into `guide_prompt_sha256` and bound
  into cached prewalk qualification proof. Changing the prompt text invalidates cached proof by
  design; confirm nothing asserts a frozen prompt digest.
- **HEAD / run-doc paths / output format:** as B0.

**Tasks:**
- [ ] Embed the concrete `todo.json` and checkpoint shapes in `guide_prompt()`.
- [ ] Truncate an over-long checkpoint `summary` instead of raising.
- [ ] Treat an absent `validation_attempted` as an empty list; keep malformed entries fatal.
- [ ] Pin every new behavior and every retained strictness with tests.

**Acceptance criteria:**
- [ ] B1-A1: `guide_prompt()` output states the `PW-##` id rule, the four TODO item field names,
      the `created_at`/`updated_at` requirement, and the single-`in_progress` rule.
- [ ] B1-A2: `guide_prompt()` output states the checkpoint fields including
      `validation_attempted` as `{command, exit_code}` objects, literal
      `ready_for_execution_model: true`, `created_at`, and the summary length bound.
- [ ] B1-A3: a checkpoint with a >500-character `summary` validates, and the normalized result
      carries a summary within the bound.
- [ ] B1-A4: a checkpoint with no `validation_attempted` key validates to an empty list; a
      checkpoint whose `validation_attempted` contains a non-object or a non-integer `exit_code`
      still raises `prewalk_checkpoint_invalid`.
- [ ] B1-A5: existing strictness is unchanged — wrong `schema_version`, mismatched run/session id,
      out-of-order `PW-##`, two `in_progress` items, and a missing `ready_for_execution_model`
      each still raise.

**Docs likely touched:** `references/prewalk.md`, `CHANGELOG.md`.

**Risk:** `standard` — touches a fail-closed validator on the prewalk transition path.
**Caution:** leniency must not weaken any identity or authority check, and must not manufacture
validation evidence.
**Affected surfaces:** `prewalk.py`, prewalk tests, prewalk reference.
**Constitution impacts:** none; authority boundaries untouched.
**Review focus:** that no relaxed bound is an identity or evidence bound.
**Focused tests:** `tests/test_native_worker_prewalk.py`, `tests/test_prewalk*`.
**Depends on:** none.

### Batch 2 [B2]: Re-read events once when a validated report first turns terminal (#242 residual)

- **Intent / why:** #242's test flakes were fixed in PR #241, but the issue was kept open for the
  cause underneath: when a validated report first flips a run to `complete`, the incremental
  monitor may still be serving a cached event summary from before the worker's final append. The
  next poll self-corrects, so a parked driver sees the final advisory signal one poll late. The
  monitor docstring already claims terminal paths re-read.
- **Non-obvious rationale:** `resolved_depth` is forced to `full` when *state* is already
  terminal. On the exact poll that first turns terminal, state is still `running`, so the force
  does not apply. That single boundary is the whole defect.
- **Build On targets:** the existing `events_reused` / `_event_log_signature` cache path and the
  existing forced-full conditions in `monitor_full_run`.
- **Owned surfaces:** `scripts/cobbler_runtime/full_run_monitor.py`,
  `tests/test_full_run_supervisor.py`.
- **Forbidden surfaces:** the event validation contract itself; report validation; credential
  paths.
- **Acceptance evidence:** a monitor poll whose cached summary predates the final events append
  returns the final event signal in the same poll once the report validates as complete.
- **Failure modes / pitfalls:** the re-read must stay inside the existing credential-grant guard;
  it must not run when the grant context is unverified, and it must not turn every healthy poll
  into a full re-read.
- **HEAD / run-doc paths / output format:** as B0.

**Tasks:**
- [ ] Force one full events re-read when a validated report first reports terminal status while
      events were served from cache.
- [ ] Add a regression test that reproduces the one-poll lag without the fix.

**Acceptance criteria:**
- [ ] B2-A1: with a cached event summary that predates the worker's final append, one
      `monitor_full_run` call on a validated complete report surfaces the final event type.
- [ ] B2-A2: an ordinary healthy non-terminal poll still reuses the cached summary (no extra
      re-read).
- [ ] B2-A3: the re-read never runs when the launch credential context is unverified.

**Docs likely touched:** `CHANGELOG.md`.

**Risk:** `standard` — supervisor timing family.
**Caution:** do not widen the cache invalidation rule; this is one boundary, not a policy change.
**Affected surfaces:** `full_run_monitor.py`, supervisor tests.
**Constitution impacts:** none.
**Review focus:** that the cache remains sound and the guard order is preserved.
**Focused tests:** `tests/test_full_run_supervisor.py`.
**Depends on:** none.

### Batch 4 [B4]: Record the observed effective route, not the requested one (#258)

- **Intent / why:** `qualify_prewalk_live` initialises `checks["route_change"] = True` and never
  derives it from provider evidence. The success artifact then copies the *requested* route into
  recorded proof. If a CLI accepts a resume but ignores an unsupported model or effort override,
  the artifact certifies a route that never ran.
- **Non-obvious rationale:** this must not fail closed. Only Codex is known to publish an
  effective-route signal (an `item.completed` whose item type is `error`, naming both the
  recorded and the resuming model). Claude Code, Grok Build, and Oh My Pi publish nothing
  comparable today. The honest outcome is a recorded evidence tier, not a blocked qualification.
- **Build On targets:** `PrewalkQualificationResult`, the existing canary event scan, and the
  host-profile capability metadata that already varies behavior per host.
- **Owned surfaces:** `scripts/cobbler_runtime/native_worker.py`, prewalk qualification tests,
  `references/prewalk.md`.
- **Forbidden surfaces:** the transition validators (B1 owns those); merge/landing authority.
- **Acceptance evidence:** a Codex canary transcript carrying the model-switch item records an
  observed route and an `observed` evidence tier; a host with no signal records `unobserved`
  and still qualifies; a transcript naming a model other than the requested one fails
  `route_change`.
- **Failure modes / pitfalls:** the Codex signal arrives as `item.completed` with an inner item
  type of `error`; the top-level type is what error classification reads, so parsing must look at
  the inner item and must not start classifying these as provider failures.
- **HEAD / run-doc paths / output format:** as B0.

**Tasks:**
- [ ] Add an observed effective route (model, effort, phase) to `PrewalkQualificationResult`.
- [ ] Derive `route_change` from observation where a host publishes one; stop initialising it to
      `True`.
- [ ] Record the evidence tier in the success artifact.
- [ ] Test all three outcomes: observed-and-matching, observed-and-mismatched, unobserved.

**Acceptance criteria:**
- [ ] B4-A1: `checks["route_change"]` is no longer initialised to `True`; its value is derived.
- [ ] B4-A2: a Codex-shaped model-switch item populates the observed route with both model names
      and does not trip provider-error classification.
- [ ] B4-A3: an observed route contradicting the requested route fails qualification with a
      route-change reason.
- [ ] B4-A4: a host publishing no signal still qualifies, and the artifact records the weaker
      tier explicitly rather than claiming behavioural proof.
- [ ] B4-A5: existing qualification checks (session continuity, worktree binding, stream identity,
      packet count, guide retention) are unchanged.

**Docs likely touched:** `references/prewalk.md`, `CHANGELOG.md`.

**Risk:** `high` — qualification is a fail-closed gate; a wrong derivation blocks real runs.
**Caution:** absence of a signal is not evidence of a failed override. Never let a missing signal
become a failure.
**Affected surfaces:** `native_worker.py` qualification, prewalk reference.
**Constitution impacts:** none; qualification cannot grant authority either way.
**Review focus:** the fail-open/fail-closed boundary, and honesty of the recorded tier.
**Focused tests:** prewalk qualification tests.
**Depends on:** none.
